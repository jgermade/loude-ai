Prune
behind makes the oldest turns give up their code and keep their exchange: the span becomes the line that cites it, the question and the answer stay. What it buys is not tokens — on the same 20 turns the prompt moves −0.3% and nothing is evicted at all, 0 turns dropped against 13. No accuracy measurement.
Results
Both replace a tool result behind the prune line with the line that cites it, and both are inert without prune. What they differ on is which results: cited_reads gives up what could be asked for again — a file's bytes, a directory listing — and keeps what a command found. cited gives up a command's output too.
The 32 752 tokens this rule freed over 20 turns were measured on a corpus where every turn read a 136 KB file and hit the 8 KiB cap, and where no command output was ever pruned. So cited_reads is the whole of that measured saving, and cited is that saving plus a claim nothing has checked: an exit code and a test run are a record of something that happened, and a model reasoning about a cargo test it can no longer see is the open question this rule has had since the day it landed.
