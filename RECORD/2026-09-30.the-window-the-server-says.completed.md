# The window the server says

## The problem

Jesús's page reads `context 504 / —`. His `llama_cpp` profile names no
`context-limit`, so luu runs with no window: nothing is budgeted, nothing is
evicted, and a conversation that outgrows the server's context is truncated by
the server without luu knowing. The server does know. `llama-server` b11236
answers `GET /props` with `default_generation_settings.n_ctx = 32768`, the
window it was started with. Without `-c`, that is the model's own trained
window.

The rule so far, from
[`an-openai-compatible-backend`](2026-09-01.an-openai-compatible-backend.completed.md),
is that on this API the window is the server's and luu uses the one it is
told: `--context-limit`, or the profile's `context-limit`. That rule stands.
What is new is a third place to be told: **the server itself, when it says**.

## The proposal

- `Backend::window()`, beside `models()`: the window the destination is
  serving, when it can say, and `None` when it cannot. That is not an error,
  the same way an empty model list is not one.
  - **OpenAI-compatible**: `GET <root>/props` (`llama-server`: `n_ctx`, from
    `default_generation_settings` or the top level), then `GET <base>/models`
    (vLLM: `max_model_len` on the model). Neither answering is `None`.
  - **Ollama: `None`, on purpose.** There the window is not the server's but
    what luu *sends* (`options.num_ctx`), and the model's trained
    `context_length` from `/api/show` is not what the server would serve if
    told nothing. Taking it would make luu ask Ollama for a 32k KV cache
    nobody chose. Ollama's window stays the profile's to declare.
  - The engine wrapper waits for its engine before asking, as it does before
    sending.
- **Only where nothing declared one.** A flag or a profile's `context-limit`
  wins, as it always has, and luu does not ask.
- **In `serve`, asked in the background**, once the session points at a
  destination (at startup, on a new session, on a resume), because an engine
  may still be loading. When the answer comes, the destination takes the
  window (`WindowFrom::Server`, and the "the window is the server's" caveat
  drops, since the server just said) and **the stream gains a header**
  carrying it. That is the rule every other mid-session change follows: two
  stretches of one session under different windows are not comparable, and
  only a header says where the second began. A destination that moved in the
  meantime is left alone, because the answer was about the old one.
- **In `luu chat`**, asked once before the first turn, and printed:
  `window: 32768, from the server`.
- **The page** shows the session's window where the newest turn's budget has
  none. A turn built before the window was known was not budgeted against
  it, and the indicator reads `504 / 32k` only because 504 is also that much
  of the window the session now has. The page reads the settings again when a
  turn ends, which is when a window learned in the background becomes
  visible.

**Rejected.**

- *Reading the GGUF's `context_length` for an engine luu starts.* Exact only
  when nothing narrowed it: `-c` in the engine's `args`, or a server that
  fits the context to memory. The server's own answer is exact either way.
- *Passing `-c` to engines luu starts.* A choice of window is the person's,
  and the server's default is the model's own. This reads what was chosen
  rather than choosing.

## Built

As proposed. `Backend::window` (default `None`); the OpenAI backend's
`/props`-then-listing; the engine wrapper asking only once its engine is up;
`WindowFrom::Server`; `Destination::windowed`; `serve::learn_window`, spawned
at startup, on a new session and on a resume; and `with_server_window` for
`chat` and `stdio`. Ollama answers `None`, as argued.

**Against Jesús's own setup**, `config.toml` copied, his running
`llama-server`: `serve` came up with `window: 32768, window_from: "server"`,
no caveat, and the log line `the server says its window window=32768
profile="llama_cpp"`. `luu chat "hi" -p llama_cpp --no-tools` printed
`window: 32768, from the server` before its first turn.

**Tested** in `openai_wire`: `/props` gives 32 768, a vLLM-shaped listing gives
16 384, and a server that says neither gives `None`.

**The page** reads the turn's window where the turn was budgeted against one,
and the session's where it was not. It says which when they differ ("this
turn was built before the window was known"), and it re-reads the settings at
the end of every turn.
