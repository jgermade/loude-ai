# A project is a host, a folder and a session

## The question

Jesús, in one message:

> el dropup de selección de proveedor/modelo es muy alto

> button.root abre la modal de elección de carpeta de trabajo, debería
> tratarse como un proyecto, donde se elija la carpeta de trabajo, el runtime y
> el modelo
> en el listado de carpetas de trabajo de la modal, estaría bien mostrar las
> que están inicializadas con git

> la idea es que en esa modal, se puede elegir tanto la carpeta de trabajo como
> el host de la carpeta de trabajo, por tanto, eligiría:
>
> host > carpeta de trabajo > runtime + modelo
>
> sobre el host, la idea es que pueda elegir entre localhost o alguno remoto,
> que pueda añadir ahí mismo

Asked what a remote host *is*, he chose: **another `luu serve`**, reached
through this one.

## What it was

- **The model menu** in the chat's foot had a fixed height, `min(60vh, 26rem)`,
  so it would not move its top edge each time the pointer crossed a provider
  whose list was a different length. With two providers and four models that
  is a menu that is mostly empty.
- **The folder picker** chose a subdirectory of the folder `luu serve` was
  started in, and nothing else. Where a session sends and what it may run were
  a second modal (the session starter, behind the chat head's `+`) that knew
  nothing about the folder. A listing did not say which folders are
  repositories.
- **There was one host.** The page talks to the server that served it.

## What it is

### The model menu fits its first list

The height is measured once, when the list it opens on arrives: enough for
the providers and the current provider's models, clamped between 8 and
`min(50vh, 20rem)`. After that it is fixed, for the reason it was fixed
before: the top edge must not chase the pointer. A longer list scrolls inside
its column.

### `repo` on a listing

`workspace::Entry` gains `repo: bool`: the directory has a `.git` in it (a
directory, or the file a worktree or a submodule leaves). One `stat` per
directory listed, against the `read_dir` already being paid. The tree and the
picker draw it as a small branch mark beside the name.

### The project modal

`button.root` opens one modal, wider than the picker it replaces, in three
columns:

```
┌ Hosts ──────────┬ Folder ────────────────────┬ Runtime ─────────────┐
│ ● localhost     │ luu / crates               │ server default ▾     │
│   workstation   │  ▸ agent-core      ⎇        │ Model                │
│ + Add a host    │  ▸ luu                      │ ollama  │ qwen2.5:7b │
│                 │                             │ mlx     │ qwen3:14b  │
└─────────────────┴────────────────────────────┴──────────────────────┘
  workstation · luu/crates · docker · ollama/qwen2.5:7b
                                   [Only the folder]  [Open]
```

- **Open** takes the folder *and* starts a session there with the runtime
  and the model. This is the session starter's *Start session*, the same
  request with the same rules. **Only the folder** is what the picker did,
  and keeps the session on screen.
- **The forced first visit is the same modal, locked**, as the picker was.
- **The session starter stays**, behind the chat head's `+`. It is the one
  way to *Continue here*, which moves a history and has nothing to do with a
  folder.

### A host is another `luu serve`

```toml
[host.workstation]
url = "http://ryzen.local:7878"
token-file = "~/.config/luu/ryzen.token"
```

- **The local server is the proxy.** `/h/<name>/api/*` and `/h/<name>/ws*` are
  forwarded to the host's URL with `Authorization: Bearer <token>`, the token
  read from its file by the same `secret::read` that reads a provider's key and
  the server's own token, with the same mode check. `/h/<name>/` and every
  other path under it are **this** server's own page.
- **So the page needs no change to talk to a host.** Every request it makes is
  `./api/…`, relative. Served at `/h/workstation/`, those resolve to the
  proxy. The socket URL was the one absolute path, and it now keeps the
  prefix.
- **The page is always this machine's build.** The host answers the API, and
  the wire version is what makes two builds refuse each other out loud. A host
  whose page is older than this one does not get to draw it.
- **Choosing a host navigates.** Picking `workstation` in the first column
  lists *its* folders, runtimes and models, through the proxy. **Open** starts
  the session on the host, remembers the folder for the host's base, and loads
  `/h/workstation/`. `localhost` is `/`.
- **The remembered folder is keyed by host too**: `luu.root:<base>` stays the
  key for this machine, so nothing remembered is lost, and a host's is
  `luu.root@<name>:<base>`. Two Macs with the same `$HOME` are two keys.

**Adding a host is the sub-modal** over the project modal, the way an engine is
added over Settings: a name, a URL, a path to the token file. It writes
`config.toml` through the same `Config::write` that refuses a file the loader
would refuse.

## Why this fits the design

[*A session stays on the host that made it*](../luu-design.md#a-session-stays-on-the-host-that-made-it)
still holds. A session on `workstation` is made by `workstation`'s `luu serve`,
its history and evidence are written there, and nothing moves. The local server
carries bytes and keeps nothing. This is the browser being able to reach a
second server without a second tab and a pasted token. It is not a session
crossing a machine.

## The rules

- **Only on loopback.** The proxy and `PUT /api/hosts` answer only on a
  server bound to loopback, which is the rule `PUT /api/providers` already
  keeps. Off loopback, a bearer token for *this* server would carry the host's
  authority, approvals included, to anyone holding it. That is a larger grant
  than the token was issued for.
- **A name, never a URL.** The page asks for `/h/workstation/…`, and the URL is
  what `config.toml` says. The browser cannot point the proxy anywhere a person
  has not written down on this machine. Names are `[A-Za-z0-9_-]+`.
- **The token is a path, never a value**, for the reason a provider's key is:
  the page never holds it, and the file's mode is checked.
- **The incoming `Authorization` is dropped** before forwarding. This server's
  token is not the host's.
- **An unreachable host is a 502 that says which host and why.** The modal
  probes each host with `GET /h/<name>/api/settings` and shows the answer on
  its row.

## What it costs

- **A WebSocket client in the binary.** `tokio-tungstenite` was a
  dev-dependency for `tests/serve_ws.rs`. It is a dependency now.
- **Every request to a host takes two hops.** On a LAN that is a millisecond.
  The `events` stream and the terminal are forwarded as streams, not buffered.
- **A host's icons are the host's.** `/api/icons/*` goes through the proxy like
  everything else, so the icon theme is the one the host has set. That is
  right for the files, which are the host's, and surprising the first time.

## Rejected

- **SSH to the other machine, with the session here.** Every
  `/api/workspace/*` route, the terminal and every tool call would need a
  second implementation over ssh. It is the worker seam made remote. That may
  come one day, and it is not this.
- **The browser talks to the host directly** (`http://ryzen.local:7878/?token=…`).
  That needs CORS on every route, and puts the token in a URL a person pastes,
  in history, and in the referrer. It also leaves nothing for the modal to
  list.
- **Proxy the host's own page too.** The page would then be whatever version
  the host runs, and a host one release behind would draw a modal without the
  host column, with no way back to `localhost`.

## Still open

- **The folder does not narrow the session.** As with the picker, a root is a
  prefix the *page* puts on what it lists. The model still sees the whole
  sandbox base. A project that is a sandbox is the narrowing record's
  question, not this one's.
- **A host's own hosts are not offered.** Under `/h/workstation/`, the host
  column is still this machine's list, read from `/api/hosts` at the root. No
  chaining.
- **Rotating a host's token** is editing a file, and nothing tells the page
  that the next request will fail until it does.

## Appended 2026-10-02: landed

As proposed, with these differences found by running it:

- **The host form has to sit inside the project modal's body** to be its
  child. Placed beside the modal, it opened as a second modal with its own
  head, centred on the window. `components/modal.html` decides it is a child
  by finding an open `dialog.modal` around it, and a sibling has none.
- **A host that does not answer said only "error sending request"**, which is
  reqwest's top-level message. `hosts::chain` now walks the error's sources,
  so the row's tooltip and the form say `tcp connect error: Connection refused`.
- **A guarded host wants the client's hello before anything else**, through
  the proxy as anywhere: `tests/hosts.rs` sends a prompt first and gets the
  `refused … version` answer. That round trip is the test that frames go both
  ways.
- **The model menu** is fitted once to the providers and the first list
  (floor 8rem, ceiling `min(50vh, 20rem)`).

Checked by `tests/hosts.rs` (two real `luu serve`, one guarded: the hop, the
token, a missing host, the page under the prefix, a foreign `Origin`, the
socket both ways and refused without an `Origin`), `workspace.rs` (the `repo`
mark), `provider.rs` (a host's name and URL), and the live suites, 37/37. By
hand: a host added from the sub-modal, a host that is down, and *Open* on
another host landing on `/h/<name>/` with that host's session and model.

### Still open, added

- **`wss://`.** `tokio-tungstenite` is built without TLS, so an `https://` host
  answers its API and refuses its sockets. One feature flag, and a host behind
  TLS to try it against.
