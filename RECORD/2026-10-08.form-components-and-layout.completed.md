# Form components and layout

A self-contained form component library in `web/components/`, adopting the
rules established in [`2026-09-28.components-of-our-own`](2026-09-28.components-of-our-own.completed.md),
and replacing ad-hoc form markup across Settings, modals, and inspectors.

## The problem

While controls like `Segmented`, `Rail`, `SaveButton`, and `Dropup` were
migrated to dedicated, self-contained components in `web/components/`, form
controls remained heterogeneous and fragmented:

- Raw `<input>`, `<select>`, `<textarea>`, and `<input type="checkbox">`
  were duplicated across `provider-form.html`, `engine-form.html`,
  `host-form.html`, `authority.html`, `session-starter.html`, `runtimes.html`,
  `general.html`, and `project.html`.
- `<select>` had no global base style in `app.css` (only `.providers select`),
  so native selects in modals had browser default chrome, inconsistent heights,
  and unstyled dropdown carets.
- `<textarea>` was styled only via scoped rules in `authority.html`.
- Global `input` rules in `app.css` had `flex: 1` unconditionally, which forced
  checkboxes and radios into flex stretching unless explicitly overridden.
- In `.settings`, `<dd>` used `align-items: baseline;`, causing inline validation
  warnings (`<span class="warn">`) to squish beside 100%-width inputs or wrap
  awkwardly without occupying their own full line.

## The components

Following the rule for `web/components/`: **every component imports nothing**,
all properties arrive as props or slots, changes leave via `$updateModel` or
`$emit`, styles are `<style scoped>`, and tokens carry fallbacks.

| File | What it is | Contract |
| --- | --- | --- |
| [`text-input.html`](../web/components/text-input.html) | Single-line text, number, url, search or password input with unified borders, focus ring, optional clear button, prefix/suffix affixes, and `size="num"` / `size="small"` variants. | `:model`, `:value`, `placeholder`, `disabled`, `readonly`, `size`, `warn`, `invalid`, `clearable`, `prefix`, `suffix`, `@input`, `@change`. |
| [`select-input.html`](../web/components/select-input.html) | Dropdown select with custom chevron caret, unified focus ring, and theme tokens. Accepts an `options` array or slotted `<option>` tags. | `:model`, `:value`, `options`, `placeholder`, `disabled`, `size`, `warn`, `invalid`, `@change`, `<slot>`. |
| [`checkbox.html`](../web/components/checkbox.html) | Accessible custom checkbox with hidden native input, 4px rounded box, animated SVG checkmark, and slot for rich labels. | `:model`, `:checked`, `disabled`, `label`, `description`, `@change`, `<slot>`. |
| [`toggle.html`](../web/components/toggle.html) | Sliding switch with accessible `role="switch"` and smooth spring transition (`cubic-bezier(.32, .72, 0, 1)`). | `:model`, `:checked`, `disabled`, `label`, `size`, `@change`. |
| [`textarea-input.html`](../web/components/textarea-input.html) | Multiline textarea matching the input styling, focus rings, and resize control. | `:model`, `:value`, `placeholder`, `rows`, `disabled`, `resize`, `warn`, `invalid`, `@input`, `@change`. |
| [`form-field.html`](../web/components/form-field.html) | Structural wrapper for labels, inputs, caveat/warn messages, error alerts, and notes. | `label`, `note`, `warn`, `error`, `required`, `layout`, `<slot>`, `<slot name="badge">`, `<slot name="note">`. |

## Where they are used

- **`web/views/settings/models/provider-form.html`**:
  `Name`, `URL`, `Model`, `Window`, `Key file`, and host confirmation now use
  `TextInput`; `Backend` and `Tool calls` use `SelectInput`; `Default` uses
  `Checkbox`.
- **`web/views/settings/engines/engine-form.html`**:
  `Name`, `path`, `Version`, `Variant`, `Port`, `Arguments`, and `Ready within`
  use `TextInput`; `Kind`, `Binary`, and `Model` use `SelectInput`; `Provider`
  uses `Checkbox`.
- **`web/views/inspector/tree/host-form.html`**:
  `Name`, `URL`, and `Token file` use `TextInput`.
- **`web/views/settings/sessions/authority.html`**:
  Draft and Plan note inputs use `TextareaInput`.
- **`web/views/chat/session-starter.html`**:
  `Provider` and `Runs` use `SelectInput`; `Model` uses `TextInput` with datalist.
- **`web/views/settings/runtimes/runtimes.html`**:
  Posture name and policy picker in `.adding` use `TextInput` and `SelectInput`.
- **`web/views/settings/general/general.html`**:
  Icon theme custom path uses `TextInput`.
- **`web/views/inspector/tree/project.html`**:
  Runtime and provider selectors use `SelectInput`; custom model fallback uses
  `TextInput`.

## Layout & style review (`web/app.css`)

- Added unified base styling for `select` and `textarea` in `app.css` to match
  `input` in box sizing, typography, border radius, backgrounds, and focus rings.
- Fixed `input` rule applying `flex: 1` to checkboxes and radios: checkboxes
  and radios now declare `flex: none` and `accent-color: var(--accent)`.
- Improved `.settings` grid layout: added explicit vertical centering for
  control rows, and gave `.settings dd > .warn` and `.settings dd > .error`
  `flex-basis: 100%` so inline validation alerts wrap cleanly below inputs
  without breaking the flex rhythm.

## What was checked

- `cargo test --workspace`: all 51 `serve_ws` integration tests, `worker_seam`,
  `hosts`, `stdio`, `select_probe`, `store_parity`, and `server_config` pass.
- `cargo clippy --workspace --all-targets`: 0 warnings.
- `cargo fmt --all --check`: clean formatting.
- Headless selector compatibility: test locators such as
  `form.locator("dd input").first()`, `form.locator('input[placeholder="..."]')`,
  `form.locator('select')`, and `form.locator('textarea')` resolve to the inner
  native form controls rendered by the components.

## Rejected

- **Global styling without components**: Writing only CSS rules in `app.css`
  would leave template code with repeated boilerplate for carets, checkboxes,
  and clear actions, and wouldn't solve consistent `:model` binding or custom
  ticks.
- **Third-party form dependencies**: Follows `RECORD/2026-09-28.components-of-our-own.completed.md`;
  no external npm form libraries were installed.
