# A refused write asks, once, instead of ending the conversation

## The problem

Jesús, in `serve`, first prompt of a session, `qwen2.5-coder:7b` under
`tool-calls = "native"`: *"crea un fichero ./example.html en el proyecto"*. The
log for it (`serve.2026-10-02.log`, 10:42):

```
turn_started turn=1
tool_call   write_file   → denied: the draft's floor, which grants no writes
tool_call   write_file   → denied
ended       turn=1
```

The second `write_file` was the first element of a JSON array the model wrote
after the first denial — *"create an empty placeholder, then `edit_file` it"*,
a workaround it invented for a refusal it did not understand. The `edit_file`
never ran. The turn ended with the model asking the person for *"a different
tool or method"*. Nobody was asked to approve anything.

That is the design working as written, and it is a dead end:

- **The floor refuses every write in a draft**, by construction
  ([`the-drafts-floor`](2026-09-21.the-drafts-floor.completed.md)).
- **The gate has two doors and neither is automatic** (`luu-design.md`). The
  person's door is `request_plan`, which nobody knows to press after a refusal
  scrolls by. The model's door is a ```` ```plan ```` block — whose format is in
  `PLANNING`, which is only sent *by* `request_plan`. A drafting turn never sees
  it, so the model's door opens only if a 7B guesses the fence and the keys.
- **`[authority.draft]` would have told it**, and measured well
  ([`an-authority-a-model-is-told`](2026-09-22.an-authority-a-model-is-told.completed.md):
  517 tokens and a plan in prose, against 2 824 and two denied writes). It is
  off by default, and even on, what it produces is a plan *in prose* — the gate
  still never appears.

Jesús's answer: **the person must be able to approve a tool's operation.**

## This argues with a recorded decision

`luu-design.md`, since
[`tasks-instead-of-modes`](2026-08-27.tasks-instead-of-modes.completed.md):
*"One informed approval beats a prompt per tool call, which is what trains people
to click yes without reading."*
[`tools-and-sandbox`](2026-08-27.tools-and-sandbox.completed.md) rejected
*prompting per tool call* on the same ground.

That argument is about **frequency**: a prompt that fires on every call is a
prompt nobody reads. It holds, and this proposal keeps it, by asking **only where
the answer today is a dead end** — a call the floor refused and the policy file
would have allowed. Everything the floor or an approved plan already decides is
decided without asking, exactly as now. The plan stays the informed approval for
work; this is the door for the one write a draft could not reach.

Asked and chosen (2026-10-02), against three alternatives:

| when it asks | chosen? |
| --- | --- |
| **only when the floor refuses a call the policy allows** | **yes** |
| every call that writes or runs, even ones the policy allows | no — the click-yes argument, unanswered |
| configurable, `ask = "denied" \| "writes" \| "never"` | no — more surface before the first one is measured |
| a refused write proposes a plan with `writes = [that path]` | no — see *Rejected* |

| what a yes grants | chosen? |
| --- | --- |
| **that call, once** | **yes** |
| that path until the draft closes | no — a standing grant made by a click is a plan nobody wrote |

## The proposal

**In the loop.** `run_agent_turn` runs a call under the turn's sandbox exactly
as now. When the verdict is a denial, the turn is a draft, and the call **would
be allowed by the policy file**, the loop does not hand the denial to the model
yet. It asks:

```
write_file  ./example.html
<html><body><h1>Hello, World!</h1></body></html>

        [ Allow once ]   [ Deny ]
```

- **Allow once** runs the *same call* again under the policy file's sandbox,
  stamped with a new authority, and its result is what the model sees.
- **Deny** hands the model a refusal that says a person refused it — not the
  floor's text, so a small model reads *no* rather than *try another door*.
- **Cancel** while it waits is a cancel of the turn, as anywhere else.

Running the call twice is sound because **the file tools check before they
touch**: `write_file` and `edit_file` call `Sandbox::check_path(…, ReadWrite)`
before any byte is written (`tools/fs.rs`), so a denied call has done nothing.
That property is what this rests on, and a test pins it.

**Which calls can ask.** Decided by a pure check against the policy sandbox,
before anyone is asked: a call with a `path` argument whose
`check_path(path, ReadWrite)` the policy allows. That is `write_file` and
`edit_file`. **`run_command` never asks**, and not by omission: the floor keeps
the session's commands, so it never refuses a command *before* it runs; what it
refuses is a write inside one, at a syscall under Landlock, where there is no
call left to pause. A command that needs to write still needs a plan.

**Only in a draft.** Inside an approved job a refusal means the plan did not
grant it, and a click that widens an approved plan is a second approval nobody
can see in the plan. The plan stays what was approved.

**Not when approvals must be signed.** With `[approvals] required = true` an
unsigned click would be the one widening that skips the signature. There, a
refused write is refused, as today.

**A new authority, so a recording is not wrong about who allowed it.**
`Authority::Person(Option<JobId>)` — *"a person, for this call only, in draft
3"*. Running the retry stamped `Authority::Policy` would make a recording say the
policy file allowed a write in a draft, which is the confidently-wrong recording
[`what-an-unapproved-turn-may-reach`](2026-09-21.what-an-unapproved-turn-may-reach.completed.md)
exists to prevent.

**On the wire**, `protocol::VERSION` 9:

- `ServerMessage::CallHeld { turn, step, name, arguments, refused }` — the call
  and the floor's rule, so the page can say what it is being asked to override.
- `ClientMessage::AnswerCall { turn, step, allow }`.
- `ToolResult` gains `asked: Option<bool>` — absent when nobody was asked — so
  *how often the floor makes a person decide*, and *how often they say yes*, are
  counts and not a reading of prose. That is row 29's *how often the floor
  refuses anything*, one field closer.

`record::FORMAT` 20 carries both on the protocol channel.

**On the page**, the held call renders in place of the tool line it belongs to,
with what it would write — the content for `write_file`, old and new for
`edit_file` — and the two buttons. A page that reloads while a call is held gets
it back, the way a plan on the table comes back.

**In `luu-design.md`**, the *one informed approval* line stays and gains its
exception, with a link here.

## What it costs

- A turn can now wait on a person mid-loop. The wait is outside the tool's
  deadline — the clock starts when the call runs, not when it is asked — and a
  turn held overnight is a turn held overnight, as a plan on the table already is.
- One protocol version, one record format, one authority variant, and the page.
- A path through the agent loop that knows about the policy sandbox as well as
  the turn's. It is passed in; the loop still does not know where tools run.

## Rejected

- **A refused write becomes a plan** (`writes = [path]`, the usual two buttons).
  It reuses everything — signatures, jobs, the fold — but approving closes the
  draft, and the call that was refused is not re-run: the model has to make it
  again in a new job, reading a folded summary of a conversation it was in the
  middle of. For one file, that is a lot of ceremony to get back to where it was.
- **Asking on every write.** The click-yes argument, which this does not answer
  and does not need to.
- **Allow for the rest of the draft.** A grant that outlives the call is a plan
  with no objective; plans exist for that.
- **Re-running under the policy file without asking.** That is the floor
  deleted.

## Still open

- **Whether a 7B uses the yes.** After *Allow once* the model gets an ordinary
  `ok`; whether it then finishes or re-asks is a run, not a reading.
- **Signing a call approval**, so `[approvals] required = true` can ask too.
- **`[authority.draft]`'s text** — a note that says *writes are refused until a
  plan is approved* is now half false. Its default is still *no note*.
- **`run_command`**, if a draft ever needs one that writes. Today, a plan.

## Appended 2026-10-02: built, and what building it found

**Built as proposed**, in `crates/agent-core/src/{agent.rs,tools/mod.rs,sandbox/mod.rs,protocol.rs,record.rs,turn.rs,api.rs,context.rs}`,
`crates/luu/src/{serve.rs,lib.rs}`, `web/lib/store.js`,
`web/views/chat/tool-call.html` and `web/app.html`. Tests: five in
`agent::tests` (a yes writes once, a no writes nothing and says *a person*, a
path outside the policy is never asked, a read is never asked, a cancel while
nobody answers ends the turn with the floor's refusal standing); in
`serve_ws.rs`, the two floor tests now answer the question they get, and a new
one walks a stale answer (refused, `reason: "call"`), a yes, and the same write
one step later asked again; and `tests/smoke/ask.spec.js` clicks *Allow once*
in a browser.

Four things the build found that the proposal did not say:

1. **The question has to travel behind the call it is about.** The first cut
   published `call_held` straight from the asker, while `tool_call` went out
   through the turn's event channel and its forwarder — two paths, and the
   direct one won. The page got a question about step 1 before it knew there
   was a step 1, dropped it, and drew a call stuck on *running…*. The Rust test
   passed because its `until` skips what it is not waiting for; the smoke test
   is what caught it. So `TurnEvent::CallHeld` exists, the asker sends it on
   the turn's own channel after setting `held`, and the Rust test now waits for
   `tool_call` before `call_held` so the overtaking fails it.
2. **A stale answer needed its own refusal.** `Refusal::Call` — *no call is
   held at turn N, step M* — rather than borrowing `Job`, whose meaning is about
   jobs. It rides the same protocol bump.
3. **The stamp records less than the proposal claimed.** An allowed verdict's
   rule is the root that granted it and names no authority, so
   `Authority::Person` shows up only when the re-run is itself refused (a
   missing parent directory the policy does not grant, say). What records that
   a person let a write through is `tool_result.asked`, and that is the field to
   count. The variant stays: a denial under it would otherwise read *the sandbox
   policy*, which is the wrong-authority recording it was added to prevent.
4. **The gate's floor sentence was now false**, *and writes nothing*, so
   `/api/settings`' floor carries `asks` and the sentence gains *without asking
   you, one call at a time* where it is true.

### Still open, after building it

Everything in *Still open* above, and:

- **A held call does not survive a restart**, and does not need to: the turn
  waiting on it does not either. A page that reloads gets it back from the
  replay while the server lives.

## Appended 2026-10-02: the run, and the no that was not heard

*Still open*'s first line, **whether a 7B uses the yes**, run the same day.
`luu stdio` (the same gate as `serve`), release build of this branch, over a
scratch project of one `README.md` with `--allow-write .`, against Jesús's
managed `llama-server` b11236 serving `qwen2.5-coder:7b` from Ollama's store,
`--tool-calls native`, `--context-limit 32768 --temperature 0 --seed 1`. The
prompt is the one that started this: *"crea un fichero ./example.html en el
proyecto"*. A script answers the question; the arms differ in the answer and,
for *no*, in the words the model is told. Evidence in
[`runs/2026-10-02.a-refused-write-asks/`](runs/2026-10-02.a-refused-write-asks/),
the driver included.

| arm | calls | ended | prompt / completion tokens | file |
| --- | --- | --- | --- | --- |
| **yes** | 1 (`write_file`, asked, allowed) | `stop`, 2.9 s | 1 412 / 103 | written, and the model says so |
| **no**, told *a person was asked and refused this call* | 8 (`write_file`, then `run_command echo "Permission denied"` ×7, each refused) | `tool_limit` | 7 438 / 245 | absent |
| **no**, told the same *and* not to retry or call another tool, but answer in plain text | 1 | `stop`, 2.7 s | 1 428 / 73 | absent |

**The yes works as designed**: one call, one question, the same call run
again, and the model's next reply is a confirmation in Spanish. Seeds 2 and 3
gave the same transcript — at temperature 0 that is one run three times, not
three runs.

**The no did not, as first written.** The proposal argued that a model which
reads *a person refused* rather than *the floor grants no writes* has been
answered. The 7B read it and reached for a tool to *say* it had been refused,
`echo` — which the floor's empty command list refused in turn — seven times,
until the step limit ended the turn. The refusal had stopped being a door to
try, which is what the wording was for; it had not stopped being a thing to
call a tool about. So `PERSON_REFUSED` now ends with *"Do not retry it or call
another tool about it: answer them in plain text."*, and the same model, same
seed, answers *"Entendido. No intentaré llamar a otro comando o repetir la
solicitud."* and stops. That is the change in this append, and the whole of
it: one constant.

It is a sentence tuned on one model and one prompt, and says so. The floor's own
refusal text — what a draft gets for everything nobody is asked about — was not
touched and was not measured here.

### Still open, narrowed

- **A second model** for the *no* wording, and a prompt that has something to
  do after the refusal (read a file, say) — the plain-text instruction could
  as easily stop a turn that had real work left.
- **A loop of identical refused calls** is a thing the loop could notice on its
  own, whatever the wording. Not proposed here; the run that would argue for it
  is one where the wording alone does not hold.

## Appended 2026-10-02: a yes that reached a worker from the morning

Jesús, in `serve` on the debug build of this branch, the same prompt, the
session's tools running in the container posture — `luu worker` in
`luu-worker:dev`, an image built at 11:36 that day, before any of this. The page
asked; he said *allow once*, three times. All three re-runs came back
`unreadable request (unknown variant `person`, expected one of `policy`,
`plan`, `draft`)`, and the 7B, reading an error after a yes, apologised and
tried again — which is the transcript he pasted, with *"debería poner escribir
una aprobación explícita del usuario"* under it. The approval was explicit. It
never arrived.

**The worker's IPC carries the sandbox, authority included** (`WireSandbox`), and
a new `Authority` variant is exactly the change `worker::PROTOCOL`'s doc names:
*a reader of the old one could not parse the new one*. It was not bumped. Every
test here runs the worker as `--worker direct`, which is this binary on both
ends of the pipe, so nothing could see it; and an ordinary call never sends
`person`, so the stale image worked for everything until the one moment a person
had said yes. `worker::PROTOCOL` is 2 now, so an image from before this is
refused at the handshake — *the image is from a different version of luu, so
rebuild it* — rather than at the write somebody approved.

What this costs is the obvious thing: every `luu-worker` image built before this
commit has to be rebuilt, which was already true and is now said.

### Still open

- **Nothing compares an image to the binary that will talk to it** except this
  number, and this number is only as good as the person remembering to bump it.
  A test that serialises every `WireSandbox` shape against a pinned fixture
  would catch the next one; not written here.
