# The tree follows the disk

## The question

Jesús: when files change, the viewer (the tree and the editor) should show
it.

Until now the tree was a snapshot. It was re-read when a directory was
opened, when the refresh button was clicked, and when a tab was activated.
An agent writing a file, an editor saving one, or a `git add` in a
terminal left the panels showing the old state until somebody clicked.

## What it is

**On the server**, `crate::workspace::Watch`: the base watched recursively
with `notify` 8, using the platform's own events (FSEvents, inotify,
ReadDirectoryChangesW). Events are gathered for 150 ms after the first one
of a batch, and each batch is answered as one `Changes`:

```json
{ "paths": ["src/new", "src/new/b.rs"], "git": false, "all": false }
```

- `paths`: relative to the base, sorted, with no verb. The page re-reads
  either way, and the new listing is what says whether a path was created
  or removed.
- `git`: only the index, `HEAD` or a ref moved. A `git add` in a terminal
  touches nothing else. Every other change under `.git/` (objects, logs,
  locks) is churn and is dropped.
- `all`: more than a thousand paths in one batch. Naming them would cost
  more than re-reading.

It is served as `GET /api/workspace/events`, a server-sent event stream.
The stream owns its watcher, so a page that closes stops the watching.

**On the page**, `watchWorkspace()` in `lib/workspace.js` reads the stream
and re-reads only what is on screen:

- **The open directories each path sits under**, the base included, not
  only its parent: a directory's row carries the loudest git letter
  beneath it, so one write can change three rows. They are listed
  shallowest first. A directory whose parent's new listing no longer has
  it is forgotten without being asked for.
- **Git, at most once a second**, with one more call after a burst.
- **The active tab, quietly.** Without `loading`, which blanked the column
  and lost the scroll. Nothing is replaced when the answer is the same. In
  Monaco, the view state is saved around `setValue` when it is the same
  file. A diff tab also re-reads on `git`, because staging changes it.

A stream that drops is retried every three seconds, and the panels re-read
everything once it is back. A server that answers with an error is not
asked again. The refresh button stays.

## Decided against

- **Polling.** The page would have to ask about every open directory and
  the open file on a timer, and it would still be up to one period late.
- **The socket.** `/ws` carries the protocol, the same messages stdio
  carries. A file tree is something only the page has, and the design's
  rule is that a field only one client needs does not belong in the
  protocol.

  This is SSE beside a WebSocket, which `luu-design.md` argued against
  for *tokens* ("SSE on top gets you halfway to a WebSocket with more
  moving parts"). That argument was about putting the conversation on two
  transports. This stream is not the conversation. It has one direction,
  one message type and no state.
- **`EventSource`.** It cannot set a header. Using it would have meant
  accepting `?token=` on a second route, and that exception is kept as
  narrow as the thing that forces it (`require_token`). `fetch` with a
  reader sends `Authorization` like every other `/api/*` call.
- **One shared watcher.** Two pages on one server are rare. A shared
  watcher would need a count of who is listening, to know when to stop.

## What it reports, and to whom

A path is named only when `Sandbox::check_path` lets the panels read its
directory. A listing of that directory already names everything in it, so
a change says nothing the tree would not.

## One trap

`git status` sometimes rewrites `.git/index` to refresh its stat cache.
That write comes back as `git: true`, which asks for `git status` again.
Unthrottled, that loop could run for as long as git kept writing. The once
a second throttle is what stops it, and the test checks that a page at rest
asks nothing.

## Checked

- **`tests/smoke/workspace.spec.js`**, a new live spec. It has its own
  server in a scratch repository, because it writes files and the other
  live specs serve this checkout. On a 600-line file scrolled to 4000 px:
  - A write from outside updates the rows (about 250 ms in the probe that
    preceded the spec) and leaves `scrollTop` at 4000.
  - The row shows ` M`.
  - A folder that is made appears in the tree, and once removed it is gone,
    with no 404 for it.
  - A `git add` turns the letter into `M `.
  - Four seconds at rest ask `git status` zero times.
  - The console stays clean.
- Before the fix, removing an expanded folder logged a 404, because the
  removed folder itself was asked for. That is why directories are listed
  shallowest first.
- The live suites passed 24 of 24 against the debug binary. The first run
  failed two icon-theme tests at "asking the server…". That was the slow
  first `/api/icon-theme` read of a freshly built binary (see
  [`2026-10-01.a-slow-disk-is-one-slow-request`](2026-10-01.a-slow-disk-is-one-slow-request.completed.md)).
  Warmed, the read took **57 s**, and the rerun passed.
- The static twin passed 5 of 5. It never starts the stream: it is only
  started for a server that said hello.
- `cargo test --workspace` passed 545. `make lint` (fmt, and clippy with
  `-D warnings`) is clean.

## Still open

- **inotify and large trees.** On Linux each directory is a watch, and a
  `target/` or a `node_modules/` under the base counts against
  `fs.inotify.max_user_watches`. If the limit is hit, starting the watch
  fails, the stream answers an error, and the page stops asking.
  Measured only on macOS.
- **A posture that moves the base mid-stream** is not followed. The stream
  watches the base it started with, until the page reconnects.
