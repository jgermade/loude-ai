# Immediate Rendering and Placeholders for Async Settings Sections

When opening Settings (particularly Settings → Runtimes), the view previously appeared completely blank for 1–3 seconds while asynchronous probes executed.

1. **Immediate Rendering**: Static headers, heros, guidance descriptions, and unconstrained action controls mount and render on frame 0 without awaiting network or process probes in `:setup`.
2. **Placeholders / Skeletons**: Elements that depend on asynchronous probe results render with clean, pulsing skeleton placeholders rather than withholding the entire view.
3. **Application-wide Skeletons**: General skeleton styles (`.skeleton-pulse`, `.skeleton-bar`, `.skeleton-card`, `.skeleton-row`) in `web/app.css` reusable across the application.

## Problem

In `web/views/settings/runtimes/runtimes.html`:
```js
const check = async () => {
  busy = "check"
  took(await loadRuntimes())
  busy = ""
}
await check()
```
Because `await check()` was evaluated at the top level of `<script :setup>`, the jq79 component stayed suspended and did not mount into the DOM until all runtime probes completed:
- `docker info`
- `podman info`
- `colima status`
- `nerdctl info`
- `container info`

On macOS, running these child processes and waking sockets can take 1.5–3 seconds. During this window, the right-hand Settings pane was completely blank white space. Static UI elements that require no dynamic data — such as the hero header ("Entornos y sandbox (Runtimes)"), the introductory guidance text, the "Postures" heading, the static "server default" posture row, the "Host shell" heading and the static host shell radio choices (`loopback`, `always`, `never`) — were needlessly delayed.

The same blocking pattern affected `engines.html` (`took(await loadEngines())`), `resend.html` (`await loadResend()`), and `authority.html` (`await loadAuthority()`).

## Solution

### 1. Non-blocking setup execution
Move data-fetching calls out of top-level `:setup` `await` chains:
```js
const check = async () => {
  busy = "check"
  const ok = took(await loadRuntimes())
  busy = ""
  if (ok && (view?.tasks || []).some(t => t.state === "running")) follow()
}
check() // unawaited
```
The component mounts immediately on frame 0.

### 2. Immediate static elements
All elements that do not require server data are presented without conditions:
- Hero headers and descriptive captions
- Section headers (`Postures`, `Host shell`)
- Static policy descriptions
- Static form choices (e.g. Host shell radios, server default posture)

### 3. Skeleton / Placeholder loading states
While `!view` (or while fetching):
- Runtimes: Render placeholder skeleton cards (`.runtime-skeleton`) showing the expected runtime names with shimmering state badges ("comprobando…") and content bars.
- Postures: Render placeholder rows under the static "server default" row.
- Engines: Render placeholder engine cards showing shimmering tags.
- Sessions / Authority: Render skeleton form rows.

### 4. Global Skeleton utilities in `web/app.css`
Standardized `.skeleton-pulse`, `.skeleton-bar`, `.skeleton-badge`, and `.skeleton-card` with `@media (prefers-reduced-motion: reduce)` fallbacks.
