# What a day of use found on the page

Jesús used the page for a day and reported what got in the way, one sentence
at a time. None of it was planned, so there is no plan to close. This record
is what each report turned out to be, and **three findings about jq79** that
explain four of them, which the next person writing a component will hit
again.

## Three things jq79 does that a component has to know

**A keyed `:each` keeps a row only while its item is the same object.** The
providers table's inputs lost focus after one letter. `edit()` rebuilt every
row as a new object on each keystroke. The `:key` (`row.id`) did not change,
and the row was rebuilt anyway, `<input>` and all. It was measured by marking
the DOM nodes and typing one letter: the table survived, and the row and the
input were new. It was not new: `HEAD`'s version behaved the same. The fix
mutates the row in place, since the component's store is deep, so the change
count still follows. `workspace.js` already says the opposite about reactive
arrays assigned *from outside* a component: those must be replaced, because an
assignment inside them wakes nothing. Both are true. Inside a component,
mutate. From outside, replace, and accept that the row is rebuilt.

**`{{ }}` is not interpolated inside an attribute.** `placeholder="{{ x }}"`
renders the braces literally. Two had shipped that way: the session starter's
model field and the Models section's host confirmation. The third was the new
provider form, found by a test looking for the placeholder text. All three are
`:attrs="{ placeholder: … }"` now.

**A handler is compiled as `return (expr)`**, so `@input="a = x; b = y"` is a
syntax error that jq79 swallows: the handler does nothing, and nothing says so.
Two assignments are `a = x, b = y`.

## The viewer

**Makefile and Containerfile had no highlighting, for two different reasons.**
`Makefile` was not in `language_of` at all. `Containerfile` was mapped to
`dockerfile`, and nothing was registered under that name. Two grammars were
added:

- `tree-sitter-make` 1.1.1;
- `tree-sitter-containerfile` 0.9.2, whose own injections hand `RUN` bodies to
  bash.

`tree-sitter-dockerfile` 0.2 was rejected: it still targets tree-sitter 0.20.
Both files are found by name (`Makefile`, `makefile`, `GNUmakefile`,
`Dockerfile`, `Containerfile`) and by extension (`.mk`, `.dockerfile`,
`.containerfile`).

**Where two patterns capture the same node, the later one wins** in this
`tree_sitter_highlight`. make's query uses Neovim-era names (`@conditional`,
`@include`) that this page does not colour, so luu adds a short query that
renames them. First it went *before* make's query and lost: `ifeq` and
`include` came back plain. After it, they are keywords. The TypeScript comment
in [`highlight.rs`](../crates/luu/src/highlight.rs) says the opposite ("its own
patterns go first so that they win"), and its test passes. Why is not
understood. It is left here rather than in that comment, which is not this
record's to rewrite.

**"Reading…" is gone.** It came and went on every click and moved the file
down and back up. The body still stays empty while a file loads, so the new
file's name is never shown over the old file's text.

**A single click opens a preview tab**, VS Code's rule:

- it is in italics, and there is at most one; the next single click replaces
  it in place;
- a double click on the row or on the tab keeps it, and so does the tree's
  pencil;
- reopening a kept tab never makes it a preview again. The foot's *staged*
  toggle reopens the same id, and would otherwise have demoted it.

"Or when its content is edited" is not built, because the viewer is read-only.
`pinTab(id)` is exported for the day it is not.

## Settings → Models

**The mock a server fell back to was running and not shown.** The table
listed the file's profiles, and a file with no default has no row for the mock.
The built-in mock is now a row of its own, chosen when the file names no
default, with the *running* tag the profiles get. Choosing it writes exactly
that: no default.

**A new provider is a form in a modal**, where it used to be an empty row at
the bottom of a seven-column table. The form writes **one profile and nothing
else**: the file as the server last answered it, plus this profile, never the
table's draft. So an edit half-made in the table is neither saved by accident
nor lost, and the table merges the new name into its draft.

## The chat's foot

**The destination became a picker in two columns**: the providers, and the
models of the one in focus. It opens on the session's own provider. Hover,
click or focus moves the second column, and nothing is chosen until a model is.
A provider's models are asked for when it is first focused and kept while the
menu is open. What its engine cannot load is listed greyed, with ⚠ and the
server's reason as the tooltip.

**Who answers the gate became a dropup**, [`components/dropup.html`](../crates/luu/ui/components/dropup.html),
with the line that says what each answer means. A status bar has room for one
word and not for the explanation, and a row of segments took the width the
destination needed.

Both open upward and are `position: fixed`, measured from their button,
because the foot is `overflow: hidden`. Both are kept inside the window: the
picker is 40rem wide and at first went off the right edge in the two-column
layout, where a test could not click its footer. Escape is listened for on the
window while open, not on the menu, which may never have had the focus.

## A test that failed one run in three

*The tree shows an edit icon on hover* failed in 2 of 6 runs on `HEAD`, before
any of this, with `boundingBox()` returning `null`: the row was rebuilt in the
frame it was measured. It now measures until there is something to measure
(`boxOf`, up to 2.5 s), and passed 12 of 12.
