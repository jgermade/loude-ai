# Not a repository is an answer

## The question

Running `deploy/compose.yaml` for the first time
(step 1 of `2026-10-07.a-public-luu`) logged a 500 on
every visit. The container's `/work` is an empty volume, and
`GET /api/workspace/git-status` answered it with git's own
`fatal: not a git repository`. Jesús: *arregla primero lo del 500 de git*.

## What it was

`workspace::git_status` ran `git status` and turned any failure into
`Error::Failed`, which is a 500. So a folder nobody ran `git init` in got the
same answer as a git that crashed. The page showed git's `fatal` in red in the
Git panel, and the browser logged an error in its console. It was not new: a
laptop's `serve` started outside a repository did the same. `workspace.js`
already said what it should have been: "a workspace that is not a git
repository is an ordinary case".

## What it is

- **`git_status` answers `Option`.** `None` is *not a repository*. It is
  decided after `git status` fails, by looking for a `.git` (a directory, or
  a worktree's file) in the base or any directory above it. That is what git's
  own discovery looks for. It costs nothing when git succeeds, and it never
  parses a message that may be in another language. If there is a `.git` and
  git still failed, it is still a failure, and still a 500.
- **`GET /api/workspace/git-status` answers `{ repository, files }`.** The
  answer is `repository: false` with a 200. The page is the only consumer, and
  it keeps `files` as the map it always was, so the tabs, the diff strip and
  the diff modal did not change.
- **The Git panel says it in a sentence:** "*work* is not a git repository, so
  there are no changes to show. `git init` in it, or clone one into it, and
  this panel follows."
- **The tree listing** carries no git note for such a folder either, where it
  used to carry the `fatal`.

Checked by `workspace::tests::a_folder_that_is_no_repository_is_an_answer_and_not_an_error`
(a plain folder is `None`; a fresh `git init` is an empty map, not `None`), and
by hand: `serve` started in an empty folder answered `{"files":{},
"repository":false}` with a 200, and the Git panel showed the sentence with no
page or console error. Live suites 37/37.
