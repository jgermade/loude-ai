# Where a session runs is remembered, and a worker says why it would not start

## The questions

> al crear nuevas sessiones, deberían recordar el último runtime usado

And a session on the colima variant failed with:

```
the colima (luu-worker:dev) worker: the worker said nothing before it was asked: the worker exited (exit status: 1)
```

## The place a new session is offered

- **What is remembered.** `prefs.place` is `posture|runtime`, the same
  value the terminal's foot uses, kept in `localStorage` as `luu.place`.
  - **Written when a session starts** from the starter.
  - **Written when one moves** from the terminal's picker. The next session is
    offered where this one now runs.
- **Read, and checked first.** `openStarter` passes it through
  `stillThere`. A remembered place whose posture left `config.toml`, or whose
  runtime this machine no longer has, gives way to the server's own (`|`).
- **The starter offers the place, not only the posture.** Before this it
  offered a posture, and a session could only start on that posture's own
  runtime, though the server already took `runtime` in `NewSession`. It now
  lists every posture on every runtime it can run on, `wide — host` or
  `server default — docker · luu-worker:dev`, and sends both words.
- **One list.** The list was built in `terminal-foot.html`. It moved to
  `lib/places.js` (`placeOptions`), and both pickers use it.

## Why a worker would not start

The runtime's stderr was inherited by `luu serve`, so a runtime that refused
to start the container said why on the server's console, and the error only
had the exit code. Here colima's own line was `level=fatal msg="colima is not
running"`.

The worker's stderr is now piped:

- every line is still written to the server's stderr, as before;
- the last four are kept;
- `epitaph()` waits briefly for the exit and for the last of the stderr, and
  quotes them.

The error now ends in `the worker exited (exit status: 1): time="…"
level=fatal msg="colima is not running"`.

That run also found that colima had no instance at all, and that its
containerd shares no images with Docker. Those two facts are what
[`runtimes-and-the-machines-they-run-on`](2026-10-02.runtimes-and-the-machines-they-run-on.WIP.md)
argues from.

## Checked

- **The place:** the starter test chooses `wide|`, starts, opens the starter
  again and asserts it is on `wide|`.
- **The epitaph:** `worker_seam.rs` starts a "worker" that is a script
  printing colima's line to stderr and exiting 1. It asserts the error carries
  both the exit status and the line.

## Still open

- The place is per browser, like the rest of `prefs`. A second browser on the
  same server starts where its own last session ran.
