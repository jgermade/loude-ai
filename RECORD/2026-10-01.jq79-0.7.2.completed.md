# jq79 0.7.2

## The question

Whether the page runs the latest jq79. It did not. `web/vendor/jq79.js` was
0.6.4 (published 2026-08-24), vendored in the first commit (`725f5de`,
2026-08-26) and never touched again. The latest is 0.7.2 (2026-09-06). Jesús
asked for the upgrade on one condition: that the tests pass.

## What 0.7 changed that luu used

Read from jq79's own records at `v0.7.2`, not guessed from the commit titles.
Three changes since 0.6.4 are marked as breaking:

1. **`:attrs` is retired** (`RECORD/2026-08-27.retiring-attrs.md` in jq79).
   It now binds an attribute literally called `attrs`. luu used it 55
   times. This was the whole of the breakage: with 0.7.2 dropped in and
   nothing else changed, 13 of the 23 live smoke tests failed. The first one
   read `data-columns=""` on `.app`, where the three-column layout expects
   `"3"`. The failures were the same with a warmed binary, so the slow read
   was not the cause.
2. **A nested component renders inside a `<c79-…>` element** (the box,
   `the-wrapper-and-the-css-rename`). Nothing in luu crossed a component
   boundary with a `>` selector, so it broke nothing that was measured.
3. **Template names are resolved without `with`**
   (`name-resolution-without-with`). Nothing in luu depended on what
   changed.

## The migration

Mechanical, and done by parsing rather than by hand. Each `:attrs="{ … }"`
was split at its top-level commas, respecting quotes, template literals and
`${}`. Each key became `:key="expr"`, and a key with a hyphen kept it
(`:aria-expanded`, `:data-columns`). The converter refused a reserved name
(`class`, `value`, `checked`, `selected`) and a double quote inside an
expression. Neither came up. The twelve bindings whose expression was a
constant string were then written as plain attributes
(`placeholder="…"`, `aria-haspopup="listbox"`, `alt=""`).

The values mean what they meant. jq79's value rule did not change with the
retirement, only its spelling. A boolean attribute is removed by any falsy
value: `:disabled="replaying || …"`, which used to sit inside an `:attrs`
beside a `title`, behaves as before. Every other attribute is written unless
it is `null` or `undefined`, so `:aria-expanded="String(open)"` keeps writing
`"false"`.

## Checked

- Every view loaded in a browser on the debug server (the three inspector
  panels, a file, the four settings sections) gave no console errors and no
  warnings. 0.7 warns about retired and misspelt directives, so a missed
  `:attrs` would have said so.
- The live smoke suite passed 23 of 23 against a release binary rebuilt with
  0.7.2 and warmed first. The warm-up's first `GET /api/icon-theme` took
  **76 s**, the fourth fresh binary in a row to do so (see
  [`2026-10-01.the-page-in-web`](2026-10-01.the-page-in-web.completed.md)).
- The static twin passed 5 of 5. `cargo test --workspace` passed 545.

## Still open

- **The two behaviours reported to jq79 on this day are unchanged in 0.7.2**:
  a store held in another store wakes every line that read it on a write to
  any of its fields, and a keyed `:each` replaces the nodes whose objects are
  new even when their keys are not. Both reproductions were run against 0.7.2.
  The tree's memoized `rows` stays.
- **0.7.2 warns about a retired `:attrs`, by name.** Checked after the fact
  on a one-line page:
  `jq79: :attrs was removed in 0.7 - it now binds an attribute called "attrs"…`,
  and the element carries `attrs="[object Object]"`. The first run with 0.7.2
  was read from the test results and not from the console, which is how it was
  said that day that the retirement was silent. It is not, and the warning
  would have named the cause at once.
