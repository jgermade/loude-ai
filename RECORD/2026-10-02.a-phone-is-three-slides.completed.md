# A phone is three slides

## The question

> Sobre el modo mobile, haría que muestren tres columnas, de izquierda a
> derecha: chat, inspector, editor. Por defecto se muestra el chat, y
> desplazando lateralmente, se podría cambiar al inspector y luego al editor.
> Para su implementación, podemos usar scroll slots

## What it is

Below 760px (`NARROW`, beside `WIDE` in `app.html`) the page's layout is
`slides`:

- **A row.** The `.app` grid becomes a flex row, scrolled sideways, with
  `scroll-snap-type: x mandatory` and `scroll-snap-stop: always`. Each column is
  `flex: 0 0 100%` and snaps at its start. The swipe has no script in it.
- **The order.** It is the chat, the inspector, the content, set with CSS
  `order`, so the markup keeps the desktop's left to right. The chat is first
  because it is what a phone is for, and it is what is on screen when the page
  loads.
- **All three are drawn.** `showChat` and `showContent` are true on a phone,
  and `columns` says three, so nothing offers a switch between two: no swap,
  no column switch, no resize handles. The swipe is the switch.
- **The page moves to a column when it asks for one.** `setPane` now also
  dispatches `luu:pane`. On a phone, `app.html` answers by scrolling that
  column into view. A file opened goes to the content, and the logo and every
  other way to the chat go to the chat. The event fires even when the stored
  pane does not change, which is exactly the case on a phone: the pane was
  already *content* when the next file is opened.

## Rejected

- **A JavaScript carousel.** Scroll snap is the platform's, keeps momentum and
  the browser's own gestures, and costs nothing.
- **Reordering the markup.** The desktop is left to right as it is, and
  `order` is the phone's alone.
- **Storing which slide is on screen.** A swipe is not a preference, and the
  chat is where a phone should open.

## Checked

- **A test at 390×844:**
  - the order is chat, inspector, content, and the chat is on screen;
  - no swap and no column switch exist;
  - a scroll that stops 60% of the way lands on the inspector;
  - opening a file lands on the content;
  - the logo lands on the chat.
- **By eye:** screenshots of the three slides at the iPhone 13 profile.

## Still open

- **Not tried on a device.** Swiping over code with long lines may scroll the
  code sideways before it moves the slide, because the inner scroller takes the
  gesture until its own edge.
