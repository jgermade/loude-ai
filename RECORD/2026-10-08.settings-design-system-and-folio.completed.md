# Settings Design System, Max-Height Modal, and 3D Folio Animation

Settings was text-heavy, dense with paragraphs of internal commentary, and
lacked visual hierarchy and friendly illustration. Switching between tabs in
the modal caused awkward dynamic height recalculations (via `settle()` polling
and `ResizeObserver`), creating a jittery UI experience. Furthermore, the modal
opened with a flat scale transition rather than a tactile, physical gesture.

This change introduces:
1. A unified **Design System** in `web/app.css` (`.ds-hero`, `.ds-card`,
   `.ds-badge`, `.ds-flow`, `.ds-preview-card`, `.ds-diagram`).
2. Fixed settings modal height to maximum (`calc(100dvh - 4.5rem)`), removing
   `settle()` delays and height jumps on section transitions.
3. A 3D **Folio perspective animation**: the modal opens swinging down from an
   inclined pose where the bottom tilts forward towards the viewer (+36deg),
   pivoting below the top edge (`50% 22%`) with smooth monotonic deceleration
   (`cubic-bezier(.16, 1, .3, 1)`).
4. Visual hero banners, interactive preview cards (theme tone and column layout),
   3-step execution flows, and context caching diagrams across Settings tabs.

## Problem

The previous settings view suffered from three issues:
- **Jumpy tab transitions**: `settings.html` measured the rendered content
  height per tab using an iterative polling loop (`settle`, checking unchanged
  height for 90ms up to 700ms), followed by a height animation. Tab switching felt
  sluggish and visually unstable.
- **Unfriendly, text-dense content**: Dense blocks of technical notes without
  visual anchors or illustrations made configuration daunting.
- **Flat modal opening**: Standard modals popped in with a slight vertical slide
  and scale, without physical presence.

## Design

### 1. Fixed Modal Height
By pinning the modal height to `calc(100dvh - 4.5rem)` (with `2.25rem` clearance
top and bottom), the outer dialog stays steady. The content container (`.pane`)
scrolls vertically with `overflow-y: auto`. Tab switches are instantaneous
cross-fades (`240ms`) without any layout shift.

### 2. 3D Folio Animation
The modal uses 3D CSS perspective:
- Rotation axis: `transform-origin: 50% 22%` (just under the top rail).
- Initial state: `perspective(1200px) rotateX(36deg) translateY(-14px) scale(0.97)`.
  The bottom starts leaned forward towards the viewer (+Z direction).
- Easing: `cubic-bezier(.16, 1, .3, 1)`. No overshoot or oscillation wobble at
  the end, producing a smooth deceleration to rest.
- Exit: `perspective(1200px) rotateX(24deg) translateY(-10px) scale(0.98)` over
  `150ms`.
- Respects `prefers-reduced-motion: reduce`.

### 3. Design System Components
- `.ds-hero`: Friendly header banner with SVG icon, title, and descriptive subtitle.
- `.ds-preview-card`: Clickable visual choice cards for Monokai Dark/Light tones
  with palette dots, and column layout previews with miniature wireframes.
- `.ds-flow`: Horizontal step sequence (On-demand -> Automatic start -> Clean auto-sleep).
- `.ds-diagram`: Visual pipeline showing fixed system prefix -> resend history -> active turn.
- `.ds-badge`: Pill status badges (`.ds-badge-ok`, `.ds-badge-warn`, `.ds-badge-accent`).

All existing input IDs (`#sessions-resend`, `#sessions-authority`, etc.) and native
form controls remain intact for Playwright smoke tests.

## Rejected Alternatives

- *Animating modal height with `ResizeObserver`*: Causes layout thrashing and up
  to 700ms latency per tab click.
- *Oscillating spring overshoot (`rotateX(4deg)` -> `rotateX(-1.5deg)`)*: Produced
  a distracting hitch/jitter at the end of the opening animation.
- *Hinging at `50% 0%`*: Felt like a stiff door flap; moving the axis down to
  `50% 22%` creates balanced perspective depth as the top recedes slightly while
  the bottom comes forward.

## 2026-10-08: Pinning `.modal-foot` to the bottom

With fixed modal height, short sections (such as an empty/sparse Engines or
Models list) previously left `.modal-foot` floating in the middle of the pane
with an empty space below it.

Fixed by:
- Setting `.pane` and `.stage` to `display: flex; flex-direction: column; min-height: 100%;`.
- Setting `.section.on` and individual section panes (`.engines-pane`, `.models-pane`,
  `.sessions-pane`, `.runtimes-pane`, `.general-pane`) to `display: flex; flex-direction: column; flex: 1; min-height: 100%;`.
- Giving `.modal-foot` `margin-top: auto;` in `web/app.css`. In flex containers,
  `margin-top: auto` pushes `.modal-foot` flush to the bottom edge when content is
  shorter than the viewport, while `position: sticky; bottom: -1rem;` preserves
  sticky pinning when content overflows and scrolls.

## 2026-10-08: Child Modals, Veil Overlays, and Visual Settings Enhancements

### 1. Child Modal (`.modal.child`) and Veil Overlay (`.veil`)
- **Parent-Child Visual Hierarchy**: When a modal opens inside a parent dialog
  (e.g., `ProviderForm` or `EngineForm` opened from Settings), `.modal.child`
  drops down out of the parent's header as a sheet (`z-index: 15`).
- **Parent Header Stays Lit & Active**: `.modal-head` has `position: relative; z-index: 20;`,
  keeping it visually above the child sheet and the veil overlay. The parent's
  close button can close both modals at once without interference.
- **Dedicated `.child-head`**: Inside `dialog.child`, a `.child-head` element
  features an accent bullet, title, and close button, avoiding any `.modal-head`
  selector clashes in smoke tests.
- **Veil Overlay (`.veil`)**: Styled with `backdrop-filter: blur(4px);` and
  `background: rgba(0,0,0,.48);`, covering the parent's body and side rail.
  Clicking the veil triggers dismissal.
- **Smooth Sheet Animations**:
  - Entrance: `sheet-in` slides down from `-36px` to `0` over `0.24s cubic-bezier(.16, 1, .3, 1)`.
  - Exit: `sheet-out` slides back up to `-24px` over `0.14s`.
  - Veil entrance/exit: `veil-in` and `veil-out` fade the blur backdrop.
- **Scroll & Sticky Footer Non-interference**: Applied `scroll-margin-bottom: 5rem;`
  to list items and action buttons so programmatic and user scrolls never align
  elements beneath the pinned `.modal-foot`.
