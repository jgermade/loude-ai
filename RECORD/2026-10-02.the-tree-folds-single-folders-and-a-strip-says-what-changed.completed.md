# The tree folds single folders, and a strip says what changed

## The questions

> haz que las carpetas que sólo contengan una carpeta, sin ficheros, se
> muestren como parent/nested. El click en el nombre despliega el contenido de
> nested, click en el caret abre parent, con :hover en caret en color: black

> sobre el editor, quitamos el button.diff de la pestaña, en su lugar,
> mostramos un contenedor con info del diff justo debajo, desplazando el
> contenido del editor. Este contenedor clickable, que muestre la modal

## Compact folders

The page can only draw `parent/nested` before `parent` is opened if it knows
that `parent` holds one folder and nothing else.

- **The listing says so.** Each directory entry in `/api/workspace/tree`
  carries `only`: the chain of single directories under it, `/`-separated
  (`vscode`, `b/c`). The server reads each child directory until its second
  entry, which costs a `target/` two reads, not a walk. It follows the chain
  eight deep at most, and skips `.git` as the listing does.
- **The row.** A directory with `only` that is not itself opened is one
  row, `parent/nested`, keyed by the parent.
  - The name opens and closes the nested folder, whose contents are drawn
    under the row.
  - The caret opens the parent. That undoes the compacting and shows the chain
    a level at a time, and the nested folder may itself be compact one level
    down.
  - The caret is a target of its own, and black under the pointer.

In this checkout: `.github/workflows`, `editors/vscode`, `tests/smoke`.

## The diff strip

The tab's diff icon said *that* the file changed and nothing about how much. It
is replaced by a strip under the content's head, in the flow, so the file
starts under it rather than having its first lines covered.

- **What it says.** Each side of git that has changes (`staged`, `working
  tree`) with its lines added and taken out, `+1 −1`, or `untracked — not in
  git yet`.
- **The strip is the button.** A click anywhere on it opens the diff modal.
- **When it asks git.** It reads both diffs and counts the `add` and `del`
  lines, again only when the path or git's letters change, memoized as
  `diff-modal.html` asks.

## Rejected

- **Listing every child directory from the page** to find single folders.
  That is a request per folder per listing, where the server can answer in the
  listing it already makes.
- **Compacting only after the parent is opened.** Then `editors` would read
  `editors` until clicked, which is not what compact folders are for.
- **Counts in the tab.** A tab is a name, and it is narrow.

## Checked

- **The chain:** a Rust test asserts it on a scratch tree.
  - `a/b/c/d` with a file beside `d` gives `b/c`.
  - Two children give nothing, and so does an empty folder.
  - A `.git` beside the only folder does not count.
- **Compact folders:** a test against this checkout asserts the
  `editors/vscode` row, that the name opens `vscode`'s contents, and that the
  caret shows `editors` and then `vscode`.
- **The strip:** the old diff-icon test now asserts the strip.
  - Nothing when the file is clean.
  - `working tree +1 −1` after a write.
  - The file starts within a pixel of the strip's bottom.
  - A click opens the modal on the working tree.

## Still open

- The strip reads whole diffs to count lines. `git diff --numstat` would be
  cheaper, and would need a route of its own.
